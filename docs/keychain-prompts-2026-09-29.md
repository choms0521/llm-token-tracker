# 반복 키체인 인증창 수정

## 원인과 범위

기존 설치 앱은 `com.llmtokenbar.app` 식별자와 Developer ID 팀 `9ADWM2H336`으로 정상 서명되어 있었다. 따라서 서명 변경만을 반복 인증의 원인으로 볼 수 없다.

Claude 토큰 만료, 자동 상태 조회, HTTP 401·429 재조회가 외부 CLI 소유의 키체인 항목에 접근하면서 시스템 인증창을 띄울 수 있었다. 로그인 자동 실행 항목도 `/Applications`가 아닌 개발 빌드의 Release 경로를 가리키고 있었다.

## 변경

- 자동 읽기와 명시적인 사용자 동기화를 구분한다. 자동 조회·일반 새로고침·공용 재동기화는 인증창을 띄우지 않는다.
- Claude 설정의 `Sync Credentials`만 사용자 승인 요청을 허용한다. 다른 서비스의 재동기화는 Claude 승인을 요청하지 않는다.
- 모든 앱 `SecItem` 호출을 하나의 동기식 재귀 잠금으로 직렬화한다.
- 레거시 파일 키체인에는 공개 `SecKeychainGetUserInteractionAllowed`와 `SecKeychainSetUserInteractionAllowed`를 사용한다. 현재 SDK에서 사용할 수 있지만 폐기 예정 API 경고가 있다. 데이터 보호 키체인용 UI 플래그만으로는 레거시 접근을 제어할 수 없어 이 범위에 한정했다.
- 접근 전 상태를 저장하고 호출 후 정확히 복원한다. 상태 조회나 설정이 실패하면 실제 키체인 작업을 실행하지 않는다. 복원 실패도 오류로 알린다.
- 키체인 항목의 ACL이나 운영체제 보안 설정을 바꾸지 않는다. 토큰을 갱신하거나 CLI 자격 증명을 수정하지 않는다.
- 승인 필요 상태를 자격 증명 없음과 구분하고 설정 동기화 안내를 제공한다. 재조회 실패만으로 유효한 기존 캐시를 지우지 않는다.

## 검증

- 새 테스트에서 기존 동작을 나타내는 구현으로 실패를 확인한 뒤 수정했다.
- 전체 204개 테스트를 실제 agy 조회까지 포함해 실행했고 모두 통과했다.
- 인증 관련 테스트는 가짜 자격 증명을 사용한다. 실제 프로세스의 상호 작용 플래그 복원 테스트도 항목을 조회하지 않는다. 다만 앱 호스트의 기존 시작 동작은 자동 조회를 실행할 수 있으며, 수정 후에는 비대화형 경로를 사용한다.
- 키체인을 만들거나 잠그거나 사용자를 로그아웃시키는 검증은 하지 않았다.
- 기존 실행기 CPU 시간 테스트는 앱의 다른 작업에 영향을 받아 실패했다. EOF 콜백 횟수 검사로 바꾸고 6회 연속 통과를 확인했다. EOF 처리 수정을 제거하면 새 테스트가 실패하는 것도 확인했다.
- 독립 보안 검토에서 차단할 문제는 없었다. 시스템 플래그 직렬화·복원, 사용자 의도별 경로, 캐시 보존을 확인했다.

## 로컬 설치 기준

새 Release 빌드는 기존과 같은 Developer ID로 서명하고 기존 앱의 서명 요구 조건을 만족하는지 검사한다. `/Applications/LLM Token Bar.app`을 백업 후 교체하고, 로그인 자동 실행도 설치 경로를 사용하도록 확인한다. 이 작업은 로컬 설치이며 태그 생성, 원격 푸시, GitHub 릴리즈 또는 DMG 배포를 포함하지 않는다.

## 2026-09-30: 401·429 복구 보완

- 실행 중인 설치본은 한 개이고 서명은 정상이었다. 기본 키체인은 잠금 해제 상태였으며 절전·유휴 시간 잠금 설정은 꺼져 있었다. 토큰 값은 조회하지 않았다.
- 서버가 401로 거부한 토큰은 만료 시각이 남아 있어도 다시 선택하지 않는다. 지문만 메모리에 기록하고 해당 토큰과 일치하는 앱 캐시만 무효화한다.
- 명시적 동기화는 키체인을 먼저 확인하며 앱 캐시를 동기화 성공의 근거로 사용하지 않는다.
- 429 응답의 즉시 재시도를 제거하고 `Retry-After`의 초 또는 HTTP 날짜를 따른다. 수동 동기화도 중앙 대기 시간을 건너뛰지 않으며, 캐시가 없어도 대기 시간을 표시한다.
- XCTest 호스트에서는 앱의 실제 서비스와 자동 조회를 시작하지 않도록 했다. 모의 응답 테스트 중 실서버 조회가 나갈 수 있던 경로를 막는다.
- 전체 213개 중 212개 통과, 실제 agy 조회 1개는 의도적으로 건너뛰었다. 거부 토큰 표시와 대기 검사를 제거한 변이 검증에서는 회귀 테스트가 실패했다. 구현 전 RED 기록과는 구분한다.
- 앱 소스 변경은 네 파일의 81줄 추가·32줄 삭제로 한정했다. 인증 저장소, 키체인 ACL, 토큰 갱신 방식은 바꾸지 않았다.
- ‘항상 허용’이 유지되지 않는 원인은 미확정이다. 세부 ACL 조회는 도구 권한 단계에서 차단되어 중단했으며, 이 패치가 운영체제의 허용 기록 문제까지 해결한다고 주장하지 않는다.
